What the audit found. (1) Google onboarding uploads the photo with its EXIF/GPS (auth_onboarding_service.dart:25-29 sends the picked file's raw bytes) and then calls ref.invalidate(authProvider) (go:99), both ruled out by the Page 5 learnings. (2) It probably never uploads at all: state turns authenticated, the redirect replaces the screen, and if (!mounted) return (go:123) skips the upload. (3) Its Back is context.pop() on a route reached by go (go:432): nothing to pop. (4) $e reaches the user in 7 places (auth_provider.dart ×5, fp:46, go:141). (5) No call is bounded: a dead server spins the button forever. (6) Forgot password calls PocketBase from the screen (L4) and its success copy claims the account exists. (7) Register is reached with go, so Android Back on Register exits the app. (8) Android's native launch window is white in dark mode too. (9) ~14 colorScheme…withValues(alpha) reads, raw SnackBars, a 400ms scale and a shake.
Laws on this page: L2 compose only R1 avatar, R3 button, R3a busy spinner, R5 toast, R13 field, R14 page app bar, plus two promotions: R15 AppLogoTile (About's tile; Splash needs it too) and P1 pickCroppedPhoto (Edit Profile's picker; onboarding needs it). C3: context.t.* only. L4: screens reach PocketBase only through AuthRepository.
Key boundary. Do not touch: Backup PIN logic, encryption_sync_provider.dart, _initEncryptionKeys, updatePublicKey, _saveSession, signOut, getCurrentUser (incl. its reinstall branch), secure storage, encryption services, and the router's redirect body. Where the repository is edited (8s bound, reset, forget-Google), those methods are diffed against HEAD at function level. Context only, do not re-solve: never-refresh-the-signed-in-user, user-photos-only-load-from-a-public-field, the group-key rotation learnings, blocking-account-deletion-app-lock-mute.

Why the bound sits on the network call only (G3). A .timeout() stops the wait, not the work. Around the whole sign-in, a timed-out attempt keeps running _initEncryptionKeys while the user's retry starts a second one on the same device. On the network call it fires before anything is saved, so a retry starts clean. Same for users.create, both google-auth POSTs and the reset request. The Google account picker is user-paced and not bounded.
One screen, one error (G4). With Register pushed above Login both listen to authProvider; each now shows only errors from an action it started. Offline (G5): network actions dim once with Available online; fields, links and the photo picker stay live; nothing on Splash dims. Server message strings are never shown.
