The two known smells, confirmed

Add friend opens from 4 buttons through 3 copies of the opener (Home FAB sheet + Home empty state → _showAddFriend; Requests empty state; Create Group empty state). Each copy does reset() + its own showModalBottomSheet; Home's passes radius 20, the other two fall back to the theme's 24.

The emoji list and the grid picker exist twice: _reactionEmojis (32 entries) is declared in both message_context_menu.dart:17 and reaction_bar.dart:14; both files build their own GridView picker with different keys and heights. Worse, the menu's quick row already shows all 32, so its ＋ opens the same 32 again (decision 11).
What else the audit found. (1) Destructive rows use red labels in the message menu (color: t.error goes to icon AND label, :628, :645), breaking C4b that page 4 just added for the same file. (2) $e reaches the user twice: Could not read QR: $e (add_friend_screen.dart) and Failed to send request: $e (friend_request_provider.dart:598). (3) Raw SnackBars: Copy, the pin limit, both QR errors. (4) Who-reacted waits silently: it fetches before opening, so on a slow network the long-press does nothing for seconds; a failed fetch (catch (_) {}) opens a sheet that says “3 reactions” and lists nobody; it is not scrollable (up to 50 rows). (5) The voice sheet swallows a failed download and shows a play button that does nothing. (6) Four different handles (custom colorScheme.outline@30%, custom t.line, custom 40px, and Material's showDragHandle), three top radii (20 literal, radiusLg 20, theme 24) and six title styles. (7) The add-friend sheet: hand-built field (radius 12), FilledButtons with inline spinners, Material TabBar (amber label), no offline state, and MobileScannerController() made per gallery pick and never disposed. (8) Font sizes 13.5, 12 and 18 (off the type scale) in the menus.
Laws on this page: L3: one definition each. New shared pieces: R19 showAppSheet + AppSheetChrome + SheetActionRow (C4a's private chrome, promoted to core), R20 showConfirmDialog, C12 showReactionPicker + kReactionEmojis, C13 showAddFriendSheet. Compose only R1, R3, R3a, R5, R10b, R11, R12, R13, R14. C3: context.t.* only. C4/C4b: accent = fill only; destructive = error icon + ink label.
Frozen (logic is out of scope): what each sheet starts. message_repository_impl.dart (whole file), MessageInput's _onAttachPressed switch, _sendImage / _sendVideo / _sendDocument, media_upload_service.dart, groupAdminProvider (remove / leave / rotate / sendInvites), _guard, friend_repository_impl.dart, signOut, showDisappearingDialog's write, every callback in the message menu. Where a file holding these is edited, those methods are diffed against HEAD at function level. The one lesson-driven logic edit: AddFriendNotifier.searchByCode / sendRequest (no $e, 8s bound on the network call).

Rules

Large text: every sheet and dialog at 360×640 with textScaler 2.0, and again with Plus Jakarta Sans selected (R18): no overflow; titles and labels wrap; trailing values wrap under their own Flexible; the sheet scrolls instead of growing past 90%.
Semantics (asserted with tester.getSemantics): sheet titles are headers; the handle is excluded; disabled rows report not-enabled; destructive rows keep their label (no “red”); emoji cells are buttons named by their emoji; the voice disc is Play / Pause; the add-friend search button is Search.
Motion: Material's sheet enter/exit (≤250ms) stays; under reduced motion sheets appear without the slide (decision 8). Long-press menus keep their mediumImpact; FAB and button sheets have no haptic (today).
Copy: sentence case for strings this page owns; page 4's accepted, tested strings stay (decision 1). No $e; errors say what failed and what to do.
Out of scope: what each sheet starts (sending, upload, quality, reaction writes, friend requests, group invites and key rotation, disappearing timers), E2E and keys, the bubble (incl. the reaction chips and their ＋), the composer, Backup PIN, fullscreen media (page 9), mascots (page 10).
