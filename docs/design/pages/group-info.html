Contrast finding (C4)

Accent as text on light surfaces = 2.0–2.2 : 1. That fails. Today the screens set "You", "Admin", "Invite pending" and the "Next" label as accent text → these become ink/inkSoft text, and accent stays a fill.
error text on light surface = 3.91 : 1, which fails body copy → destructive rows show an error-coloured icon (non-text, needs ≥3:1, passes) with an ink label. See deferred decision 3.
Laws on this page: L2 compose only R1 avatar, R3 button, R4 chip, R5 toast, R7 empty state, R8 search, R9 section header, R10 settings tile, R11 skeleton, R12 status banner, C4 action sheet. L3: the disappearing dialog exists TWICE today (chat's version has the checkmark; Group Info's copy does not), so extract one. L4: group_settings_screen.dart imports message_repository_impl.dart and calls the repository from widget callbacks → move the calls onto a notifier (Requests I4 precedent). C3: 9 uses of colorScheme…withValues(alpha) across the two screens → context.t.*.
E2E boundary. Do not touch any of this: _createGroup steps (a) to (f) (key validation, key generation and wrapping, group_keys writes, rollback), removeMemberFromGroup / leaveGroup bodies (both call _rotateGroupKey), sendGroupInvite server logic. The UI wraps these; it never re-orders or re-implements them. Lost-keypair orphan rows are a known, accepted gap: see learning .trail/learnings/2026-10-28-group-key-rotation-keeps-history-only-chaitanya.md (user ruled 2026-10-29: not worth fixing). The only change allowed inside _createGroup is the exception type at the two "no encryption key" throw sites (G11).
