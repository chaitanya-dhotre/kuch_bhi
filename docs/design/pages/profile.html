Two bugs, fixed first. (1) Edit Profile cannot be reached. /edit-profile is registered (app_router.dart:163) but nothing pushes it. (2) A save does not show up. _save writes PocketBase, then ref.invalidate(authProvider) (ep:70). AuthNotifier.build returns the cached Drift user (ar:257), which nothing updated, so the old values return until a resume refresh. The invalidate also re-runs the reinstall branch of getCurrentUser (ar:266-270), which can generate and upload a new key pair. Spec: P9.
Laws on this page: L2 compose only R1 avatar (+R1a/R1b), R3 button, R5 toast, R7 empty state, R9 section header, R10/R10a settings tile, R11 skeleton, R12/strip, R13 field (new), C4a action sheet + C4b destructive. L3: the field decoration is copy-pasted per field (6 colorScheme sites in the editor alone) → one R13 function. L4: the editor imports profile_update_service.dart → the write moves onto AuthNotifier / AuthRepository. C3: colorScheme…withValues on all three screens → context.t.*.
Key boundary. Do not touch: _initEncryptionKeys, updatePublicKey, refreshSessionThrottled, signOut, deleteAccount, secure storage, and the Backup PIN screens. Profile only navigates to Change Backup PIN. The new updateProfile sends display_name, username, about, avatar and never public_key. Data flow

Today
EditProfile._save→ProfileUpdateService → PB users.update→ref.invalidate(authProvider)→build() → getCurrentUser() → stale Drift row (+ reinstall key branch)
Spec
Editor (bounded 8s / 30s)→AuthNotifier.updateProfile→AuthRepository.updateProfile: PB update → _recordToUser → _cacheUserLocally→state = AsyncData(AuthAuthenticated(user))
No invalidate, no build() re-run, no key code reached. UsernameTakenException is typed in the repository; the editor maps it to the field error. Everything else → the generic toast. A PB write that lands after a UI timeout carries the same values; the next save or resume refresh reconciles Drift.
