S5

13.7: one bubble from send to sent

Today
insert row, no server id→Step B: server message created→page fetch: no local row by server id → 2nd row inserted→Step C upload (long)→Step D: stamp id, delete the 2nd row
Spec (decision 1)
localId = generateOpId(); file + thumb registered as ready blobs; one transaction→media bubble draws the local photo at once→Step B create with id = localId; ack stamps serverId + server time→a page fetch finds the row by id: still one→Step D: mediaId, sent, latch off
Same id from the first frame to sent: the Hero tag, the blob ids and the bubble never change. A re-run (resume, Try again) converges on the same server record: duplicate id → ownership check → success.
S6

13.8: your own photo keeps its full file

Risk (decision 2): this unfreezes the send path and adds registerLocal + stored metadata to the blob store. E2E/key code stays byte-identical. Without stored metadata (decision 3) a cache hit returns no size or expiry: your photo would sit at 4:3 with no badge, and that already happens to every cached photo after a restart (smell 9).
