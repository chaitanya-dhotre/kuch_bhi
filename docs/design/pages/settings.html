What it is: a read-out of whether Android lets Kuch Bhi post notifications, plus a door to the place that changes it. It is not an in-app switch: the server hook (fcm_notify.pb.js) pushes every message and keeps no per-user preference, so an in-app toggle would lie (S9 row 2).

Status = Permission.notification.status from permission_handler (already a dependency, used by message_input.dart:7; POST_NOTIFICATIONS is declared). Granted → subtitle On, icon notifications_none. Anything else → Off. Turn them on in system settings., icon notifications_off_outlined. While unknown, or when the check throws: no subtitle (row height unchanged, R10 min 56).

Tap → openAppSettings() (the app's system page). Trailing open_in_new in inkSoft says "leaves the app", where a chevron would say "a screen of ours". Returns false → R5 Couldn't open system settings.

On resume (AppLifecycleListener.onResume) the status is read again, so coming back from system settings shows the new value without leaving the screen. Both the status read and the opener sit behind providers so tests override them.

S8

Offline & error language

Nothing on these two screens needs the network. Theme = a Drift write; notification status and system settings = the OS; version and licences = bundled. So no 38% dim and no kOfflineActionHint anywhere on this page, on purpose: dimming a control that works offline would be wrong. A grep gate keeps it true: lib/features/settings/ imports no pocketbase, dio, http or connectivity_plus.

Errors are two fixed R5 toasts (error variant). No $e or e.toString() in user-visible text; details go to debugPrint only. No server mutation exists here, so the 8s bound has nothing to bound; no PocketBase file fields and no photos, so the protected-field 404 and EXIF rules do not apply. The page never touches authProvider.
