# Shared-Component Registry (L3: pages import, never reimplement)

Date: 2026-10-17. Companion to `00-foundation.md` §7. Every shared
interaction defined ONCE here with its widget path; page specs reference
these entries by name. Adding a row = spec amendment (L2).

Access pattern: widgets read colors via `context.t` (`ColorTokens`
ThemeExtension); geometry via `WarmPopTokens` statics. No hardcoded color.

## Theme tokens (`lib/core/theme/tokens.dart`)

| ID | Token | Path | Contract |
|---|---|---|---|
| T1 | `WarmPopTokens.shadowLight` / `shadowDark` / `shadowAmoled` + `cardShadow(color)` | `tokens.dart` | Elevation shadow (foundation §4): light `rgba(52,42,28,.10)`, dark `rgba(0,0,0,.35)`. Raised cards read `context.t.shadow` — NEVER `context.t.ink`, which is near-white in dark and renders a white halo around elevated surfaces. Use `WarmPopTokens.cardShadow(t.shadow)` (one explicit BoxShadow layer) rather than Material's `elevation`, which routes the shadow through the engine's tonal path and paints materially weaker than the token (measured ~7× weaker). AMOLED uses `shadowAmoled` (a faint LIGHT edge) because its surfaces are pure black — a black shadow there gives no elevation cue. Grep-gated app-wide. |
| T2 | `bottomSheetTheme` + `dialogTheme` + `WarmPopTokens.radiusPill` | `app_theme.dart`, `tokens.dart` | Sheet: `t.surface`, `surfaceTintColor` transparent, top radius `radiusLg` (was a literal 24; decision 9). Dialog: no tint, `titleTextStyle` 20/26 w700 ink, `contentTextStyle` 15/22 ink, so C11, the rename dialog and Backup PIN's dialog match with no per-site styling. `radiusPill = 999` (foundation §4 listed it; the token was missing). Foundation §7 "Sheet" = R19, "Dialog" = R20 (page 8, 2026-10-30) |
